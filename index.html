About

What I build and how I work.

Cybersecurity M.S., an ECE degree specialized in embedded controllers, IoTs and power electronics, and IEEE first-author on machine learning for EV-charger DoS. I build security systems to understand them, then measure whether they actually hold up. When the measurement disagrees with the headline, I publish the disagreement. That habit is most of what I have to offer, and the numbers behind it are in the projects below rather than asserted here.

The thread running through the work is industrial and embedded systems, from PLCs and RAN sites to EV chargers, and what happens to their security when the cryptography underneath them has to change. Measurement first. What infrastructure does, not what the specification says it should.

Three lanes of background feed the research. Telecom OSS for ~3,500 Vodafone Idea sites during the SRAN cutover, including on-call work on migration failures. HL7 v2.5 → FHIR R4 pipelines at Solstice on Azure. IT risk and NIST CSF at iQ4, where I studied the 2016 Uber breach in depth.

  • Backend APIs in Python / FastAPI. Auth, retries that aren't optimistic, structured errors.
  • Healthcare interop - HL7 v2.5, FHIR R4, EDI 837/835. Validation at every pipeline stage.
  • Hybrid IDS - live capture and PCAP replay with optional Suricata/Zeek ingest, feeding a supervised ensemble (Random Forest, ExtraTrees, HistGB, XGBoost) with a signature-anomaly fusion layer on top.
  • Local-first AI tooling - multi-provider router (Ollama → Gemini → OpenAI → Grok → NVIDIA), bounded agents.
  • Risk → remediation in language eng teams will actually pick up. No infosec-ese.

Research Interests

The questions I keep coming back to, and what I am doing about each one now. This changes as I do.

ML for security & anomaly detection

Hybrid signature-plus-anomaly fusion, supervised and unsupervised ensembles, and the hard part nobody publishes: keeping false positives low at production scale.

Now: building eval harnesses, because a detection nobody has measured is a claim, not a control.

Critical-infrastructure & IoT/OT security

Protocol-level attack surfaces (OCPP, MQTT, CAN), EV-charging and smart-grid threat models, and where IT and OT meet and break.

Now: going deeper on industrial and EV-charging protocols beyond OCPP, which is where the IEEE work pointed.

Local-first & agentic AI systems

Bounded agents, multi-provider routing, on-host telemetry, and health-IT data integrity (HL7/FHIR). How do we get useful AI tooling without handing data to someone else's cloud?

Now: multi-agent orchestration and local LLM tooling. Reading the papers, then trying to break my own implementations of them.

Security of the post-quantum migration

Measuring whether real infrastructure actually moves to post-quantum cryptography or only looks like it has: classical-only fallback, silent downgrades, and incomplete rollouts across TLS and OT/IoT fleets. Crypto-agility, not scheme design.

Now: measurement tooling for endpoint readiness, and writing up what it finds.

I write up the research side properly on the research page: measurement work on the post-quantum migration, publications, and how I evaluate my own results.

Open to research collaboration, sharp feedback, and roles where I would keep learning. If you are working on any of this, or think I am wrong about something, tell me.

Selected Projects & Research

Things I built to answer a question. Real numbers, and the tradeoffs I would revisit.

Fusion NIDS - Hybrid Intrusion Detection

Live capture and PCAP replay with optional Suricata/Zeek ingest, feeding a supervised ensemble (Random Forest, ExtraTrees, HistGB, XGBoost) plus unsupervised detection, with a signature-anomaly fusion layer on top. Ran it through a 21,600-second stability soak: 87,533 per-packet records, 0 emitted alerts, 409 MB peak memory, 13.3 s restart recovery, then audited my own headline number and published what it does and does not prove. The honest version: 3 h 19 m of flow records, 30.9% peak capture loss, and no attack traffic in the corpus, so it is a stability result and not a false-positive rate. The IDS literature is full of claims that don't survive scrutiny. I wanted mine to.

  • Stack: Python, FastAPI, scikit-learn, XGBoost, Suricata/Zeek adapters, Pandas, Docker
  • Detection: signature + anomaly + supervised ML, fusion layer for confirmation
  • Validation: 21,600 s soak, 3 h 19 m of flow records / 0 emitted alerts / 409 MB peak RSS · 292 tests passing (CI, 2026-07-27) · 75.83% coverage at 2026-07-02 · claims self-audited (SOAK_CLAIM_AUDIT)
  • Tradeoff: chose accuracy over latency; p99 inference is 340 ms, which I am working to bring down.
View NIDS case study Source on GitHub

Detection Library - Sigma, SPL, Suricata, Zeek

The rules behind the NIDS pipeline, written out as code. Five Sigma rules + two Splunk hunts + a Suricata UA pack + a Zeek enrichment script - each one tagged with the engine it feeds (signature / anomaly / supervised / unsupervised / fusion) and the MITRE ATT&CK technique it catches.

  • Sigma: PowerShell b64, DNS exfil, C2 beacon, auth burst, SYN scan
  • SPL: beacon stddev, lateral movement chain
  • Sensor: Suricata UA anomaly rules + Zeek conn enrichment
  • Tuning: each rule documents the lever to adjust before deploying

Vector - Local-first AI Security Platform

Local-first because I don't want telemetry leaving the box. FastAPI runtime (chosen over Flask for its middleware model), multi-provider router falls across Ollama → Gemini → OpenAI → Grok → NVIDIA. Bounded agents so the model can't reach beyond the tools I've defined for it.

  • Stack: Python, FastAPI, Ollama, sqlite, Windows DPAPI for creds
  • Architecture: local-first, agent-bounded, telemetry stays on-host
  • Status: active dev. Private repo. My team uses it daily.

Long-term commercial project - case study on request.
